# Лётное поле посольства — общий план: ядро (этот прогон) и аддон (следующий прогон) — 2026-10-27

Дизайн и проверенные факты кода: `docs/idea-embassy-airfield.md` (+ «Решения пользователя 2026-10-26» в конце — главнее предложения). Техплан ядра (классы, данные, пакеты, тесты): `docs/plan-embassy-airfield-core.md`. Этот файл — сводка и **точный список работы аддона** `SiliconAgeVehicles` (`com.sva`, MODID `SiliconAgeVehicles`), чтобы его прогон начинался отсюда.

## 1. Что решено (коротко)
- Поле **только с аддоном**: `embassy.airfield` = AUTO (по умолчанию: `Loader.isModLoaded("SiliconAgeVehicles")` в момент решения о старте) | ALWAYS | NEVER. Без аддона посольства — как раньше. Старые посольства **не трогаются** (нет «X» в записи — нет поля, дооснащения нет).
- FULL — ВПП 200 × 9 сбоку вдоль главной улицы в нынешнем квадрате; запасные SHORT 90 × 7 + „Н“, HELI. Аэровокзал, Вышка КДП со Светомаяком, Перрон МС-1…МС-4, вертодром „Н“, Ангар, Колонки обслуживания, памятник «Последний челнок Литографов». ИКАО X + две буквы элемента + буква номера («Тантал-1» → XTAA).
- **ПВО посольства**: ядро строит 5 видимых «Зенитных постов Наладчиков» и даёт через API зону (256 от ядра, любая высота), позиции пушек, допуск («Знакомый» и выше, не «Враг»), прикрытие звеном, журнал 7700 (один пропуск 60 с на игрока на посольство в сутки) и строки чата. **Огонь, снаряды, радио — аддон.** ПВО игроков небо посольства по-прежнему считает нейтральным.
- Услуги — таблица §7 предложения (ядро считает и списывает КЧ, аддон обслуживает технику); газы брони у колонки — ядро, без аддона-кода. «Лётная книжка» — 2 КЧ и +5 «Доверия» за первую посадку в каждом посольстве.

## 2. Ядро — этот прогон (фазы А1 + А2)
Подробно — `docs/plan-embassy-airfield-core.md`. Общее ядро уже написано и собирается: геометрия `EmbassyAirfieldSC` (самопроверка `problem()` = null на 648 планах), правила `EmbassyAirRulesSC`, ПВО-сторона `EmbassyAirDefenceSC`, **публичное API** `com.sc.embassy.api` (API_VERSION = 1), блок покрытия `embassyAirfieldSC`, меты витрин 10–13 (пульт КДП, колонка, светомаяк, зенитный пост), регистрация кусков, решение в генерации, запись «X», охрана через реестр, сообщения вкладки, конфиг. Пакеты: **G** (решение по биомам, выравнивание по форме, земля, Достройка, посты, команда), **P** (куски поля, вид, светомаяк), **R** (охрана зоны, колонка, оплата, «Лётная книжка»), **T** (вкладка Диспетчера), **D** (lang, справочник, NEI, тесты, README).
Результат ядра: готовое, охраняемое поле, полезное и без аддона-кода (при ALWAYS): посадка в броне, газы брони за КЧ, светомаяк, вкладка с лором.

## 3. Аддон — следующий прогон (фазы А3 + А4 и ПВО посольства)

Правила прогона: ядро **не править** (нужна правка — запрос координатору ядра); аддон не ставит в посольство ни одного своего блока (охрана поля не даст, «Достройка» откатила бы) — всё виртуальное из API; бэкапы jar и src — в `MineMod/backups-vehicles`; записи в SESSIONS.md и CHANGELOG «Не выпущено»; `gradle clean build` перед установкой; коммит и релиз — только по команде. Номера строк проверены 2026-10-27 по коммиту аддона `d36403e` (другой чат работает в аддоне — перед правкой перепроверить).

### 3.1 Точка входа и версия
- Новый `com.sva.compat.EmbassyCompatSVA` — **единственный** класс аддона, который зовёт `com.sc.embassy.api.*`: в init — `Class.forName("com.sc.embassy.api.EmbassyAirApiSC")` в try (старое ядро без API — тихо выключить всё посольское), `EmbassyAirApiSC.API_VERSION == 1`, `registerHook(new EmbassyHookSVA())` (реализует `IEmbassyAirHookSC`: `apiVersion` 1, `openService`, `serviceRows`, `atisLine`, `tabAction`, `airfieldsChanged` — только пометить «перестроить», зовётся из генерации).
- `ReferenceSVA.CORE_DEP` (стр. 11, сейчас `[0.2.0,)`) → версия ядра с API (`[0.2.4,)` — уточнить номер релиза ядра).
- `ConfigSVA`: `airport.embassyAirports` (true), `airport.embassyServices` (true), `airport.embassyTowing` (true), `airdefense.embassyAd` (true — ПВО посольства).

### 3.2 Признание полосы (одна точка `vehicle/RunwaySurfaceSVA.is(world, x, y, z)`)
Блок ВПП аддона **или** `EmbassyAirApiSC.isRunwaySurface(block, meta)` (меты 0, 3, 5, 6, 7 блока `embassyAirfieldSC`; перрон, обочина, жёлтая разметка, синие огни — не полоса). Заменить проверки:
- `block/AirfieldSVA.java:35`;
- `entity/EntityVehicleSVA.java:1452` (`runway()`) и `:2633` (`onRunway()`);
- `client/GuiMapSVA.java:1117` (`RunwayMath.find` на карте);
- `client/RunwayLightsSVA.java:109` — свет только своих блоков `LIT`: для полос посольства ничего (у ядра свои огни);
- `client/AirportRenderSVA.java` (~стр. 153, краска только над своими блоками) — для полос посольства разметку **не** рисовать (она в блоках), рисовать только то, чего нет у ядра (§3.5).
Снег: покрытие ядра — не непрозрачный куб, снег не ложится (проверить в игре); запасной вариант — признак смотрит под слой снега.

### 3.3 Виртуальный аэропорт (`airport/EmbassyAirportSVA`)
- По `EmbassyAirApiSC.airfields(world)` при загрузке мира и при смене `revision(world)`: `AirportDataSVA.putEnd / putTower / putLoc / putGs / putDevice`; записи помечены «виртуальная», в NBT `AirportDataSVA` **не пишутся**.
- Ключи — обычный `dim:x:y:z` по точкам API (формат `emb:<id>:A` ломал бы `IlsPairing.station`): торцы — `thresholdKey(low/high)`; вышка — `towerDesk()` (FULL), у SHORT / HELI — колонка „Н“ (`columns()` последняя); курсовой и глиссадный — `localizer(low)` / `glideSlope(low)` **только у FULL и только у торцов с `ilsLow` / `ilsHigh`** (калиброваны «облётом Наладчиков», без `FlightCheck`; категория — `IlsCat`, как у игрока); колдун — `windsock()` (конус по ветру рисует аддон); огни рулёжки — `lights(BlockAirfieldSC.LIGHT_TAXI)`.
- Владелец вышки — «[Поселение-N]» (`info.id`), ИКАО — `info.icao`, сделать уникальным `TowerMath.unique` (стр. 71). Номера ВПП — `numberLow / numberHigh` (истинный курс, без `ConfigSVA.aptMagVar`). Ширина — `width` (9 / 7 ≤ `IlsPairing.WIDTH_MAX`), посадочная дистанция — `landingDistance(low)`.
- `AirportDataSVA.obstacle()` (стр. 959): блоки `EmbassyAirApiSC.isEmbassyBlock` — не препятствие (иначе огни и ограда ядра опустят категорию до I).
- `TowerMath.defaultIcao` (стр. 81) и ввод ИКАО на экране вышки: префикс X закрыт для новых вышек игроков (существующий код игрока на X не трогать — посольство берёт следующий свободный).
- Вышка посольства в сети: отчёт раз в секунду (`AirportDataSVA.towerReport`, `REPORT_TICKS` 60), пока в Верхнем мире игрок ближе `ATC_RANGE` 3000.
- `TowerMath.assign` (стр. 128) — в обе стороны: полоса посольства — только его вышке; вышка посольства не берёт полос игроков.

### 3.4 ATIS, CPDLC, авто-вышка, коды (`block/AtcServerSVA`, `airport/AutoTower`)
- ATIS вышки посольства в чат — только ближе 600 (TODO(balance)) или если её ИКАО — пункт назначения в МФПУ (`AtcServerSVA.tellAtis`, ~стр. 569; сейчас — всем в `ATC_RANGE` 3000); в МФПУ — по запросу. `atisLine` крюка отдаёт ту же строку вкладке Диспетчера.
- «Враг» (`levelOf(p, id) == ReputationSC.ENEMY`) — в CPDLC «ОБСЛУЖИВАНИЕ ЗАПРЕЩЕНО» (7700 — всем). Посадка в куполе (`info.inDome` / `domeAt`) — «ПОСАДКА В КУПОЛЕ ЗАПРЕЩЕНА». На полосе «занимают» место техника, игроки и враждебные мобы; одна машина на ВПП («бэктрек»); **руление по «А» за +a торцом держать, пока идёт посадка над +a торцом** (рулёжка в 7–13 от оси под заходом — риск 2 техплана).
- Коды ответчика вышек посольства — 5100–5177 (восьм.), всем, кроме «Врага»; ПВО игроков этим кодам **не** доверяет (`AirportCodeMath.friendOf` без изменений).
- Зона «Аэродром» (`TowerMath.zone`, стр. 210) — как у игрока; над куполом — «ограниченная» зона (предупреждение пилоту). Нарушение считается только по зонам владельца ПВО (`ofOwner`).

### 3.5 Огни и вид
Ядро ставит настоящие огни кромки, порогов, торцов и рулёжки (`lights(meta)`). Аддон рисует только недостающее: осевые, зону приземления, огни подхода с бегущим огнём, PAPI, огни порога; 5 ступеней яркости и АВТО.

### 3.6 Нейтральное небо (ПВО игроков) и зоны
- `block/TileEntityLauncherSVA.java:295`: к `prot` добавить `|| EmbassyAirApiSC.neutralAt(worldObj, tx, ty, tz)` **без** оглядки на `adFireInProtectedRegions` (флаг `RoeMath.B_PROTECTED` уже есть, предупреждения он разрешает). Над базой игрока (зона включённого Генератора поля) `neutralAt` = false — база в створе бережёт себя сама. Вне Верхнего мира и вдали от посольств вызов дешёвый (индекс полей ядра, без списков).
- `ZoneEditMath`: игрок не может создать запретную зону поверх нейтрального неба (`neutralAt` по точкам контура / `approachBoxes`).

### 3.7 МФПУ, ND, карта техники (`vehicle/NavDb`, `block/AirportServerSVA`)
`NavDb.SRC_EMBASSY` — в конец (после `SRC_TOWER` 5); только посольства, которые игрок знает (`EmbassyAirApiSC.knows(p, id)`: был или ближе 1024). `AirportServerSVA.syncDim` (стр. 112) сейчас шлёт всем одну копию — записи посольств отбирать по игроку.

### 3.8 Услуги, стоянка, перегон (`block/EmbassyServicesSVA` + данные мира, `client/GuiEmbassyServiceSVA`)
- Окно открывает `IEmbassyAirHookSC.openService` (щелчок по колонке **не** крадучись; крадучись — газы брони ядра). Зарядка АКБ и буфера (`BatteryMath`), водород (`FuelMath`), ремонт в ангаре (`GarageMath`; машина в `hangarBox()`), «Электролит», стоянка, перегон, аварийная (≤ 25% бака и буфера, раз в сутки, «Чужак»/«Нарушитель»), карта подхода. Цена — `EmbassyAirApiSC.quote(p, id, key, amount, free)`, оплата — `pay(...)` (ключи `EmbassyAirRulesSC.SERVICE_KEYS`, количество — в мере услуги: EU, мБ, % износа, сутки; `free` — первые сутки стоянки, первая карта; стоянку при талоне и первый перегон за сутки ядро считает само). Коды PAY_* → строки ядра `sc.airfield.pay.<key>`.
- Стоянка: свои данные мира аддона — занятые МС (`spotBox`, `spotKind`) по UUID машины и владельца, не больше 2 МС на игрока в посольстве. Борт без седока на ВПП, площадке или рулёжке дольше 2 мин (TODO) — на свободное МС, нет свободного — на «Отстой» у перрона; брошенный в куполе дольше 5 мин (TODO) — на «Отстой». Машина не пропадает. Таймер — `EntityVehicleSVA`.
- `entity/SpaceLogicSVA`: «Прыжок» корабля на поле — только на „Н“ (`helipadBox`), на ВПП — отказ.

### 3.9 «Лётная книжка» и вкладка
- Первая посадка: ответчик включён (`AirDefenseSVA.xpdrOn`, стр. 661), машина остановилась на МС / „Н“ → `EmbassyAirApiSC.firstLanding(pilot, id)` (ядро даёт награду один раз).
- Вкладка Диспетчера: `serviceRows` (≤ 8 строк: свои машины на МС, цены, состояние вышки), `atisLine`, `tabAction("service")` — то же окно услуг.

### 3.10 ПВО посольства (новое, аддон; `airdefense/EmbassyAdSVA` + данные)
- **Где:** для каждого `airfields(w)`, около которого есть игрок: зона — `EmbassyAirApiSC.adZoneAt(w, x, z)` (256 от ядра, любая высота; `adRadius`; **над базой игрока** — зоной включённого Генератора поля, `EmbassyAirfieldSC.playerBaseAt` — зоны нет, `-1`; `info.inAdZone` — голый круг, для огня не годится), огневые точки — `info.adPosts()` (пушки `AA_POST` ядра на постах 5 × 5).
- **Цели — только техника в воздухе:** `EntityVehicleSVA` в зоне и `airborneForAtc()` (`EntityVehicleSVA.java:450`). Никогда — пеший игрок, игрок в броне / на джетпаке (не техника), ничего на земле. Беспилотная машина в воздухе (`AirDefenseSVA.manned`, стр. 666 — false) — открытый вопрос прогона (рекомендация: цель, предупреждение владельцу, если он в сети).
- **Не цель**, если хоть один на борту (`riders()`, `EntityVehicleSVA.java:3547` — пилот, экипаж, пассажиры) — `EmbassyAirApiSC.holdFire(rider, id)`: допущен («Знакомый»+, не «Враг»), под прикрытием допущенного товарища по звену рядом (`escortOf`; аддон может добавить «товарищ тоже в воздухе»), идёт его пропуск 7700, или борт над базой игрока (ядро; ревью 2026-10-27).
- **Порядок:** вход в зону → `EmbassyAirApiSC.requestWarn(rider, id)` каждому на борту (журнал ядра: **одно предупреждение на игрока на посольство в игровые сутки**; конец разворота борта — самый ранний из ответов седоков; уже предупреждённый сегодня — конец в прошлом) и, если предупреждение новое, `tell(rider, id, AD_WARN, позывной)` + та же строка (`adLine`) по радио вышки посольства (HUD / журнал CPDLC) → до конца разворота (`warnSeconds()` 10) борт должен уходить: **сближается с полем или снижается к нему — огонь сразу** (посадка за время предупреждения — не способ пройти) → всё ещё в зоне и не `holdFire` → `AD_FIRE` и огонь; вышел из зоны → `AD_LEFT`, бой сброшен (повторный вход в те же сутки — `AD_FIRE` без нового предупреждения); стал допущен / прикрыт / над базой игрока — огонь прекращён.
- **7700** (код ответчика `XpdrMath`): первый раз в сутки на посольство — `requestPass(pilot, id)` → PASS_GRANTED: `AD_PASS`, огонь держится 60 с (`passUntil`); PASS_USED — `AD_PASS_USED`, огонь не держится (в отличие от ПВО игроков, где 7700 — АВАРИЯ, никогда не цель: `RoeMath.classify`; правила `RoeMath` для ПВО игроков не менять); PASS_RUNNING — ничего; PASS_ADMITTED — не цель и так. Конец пропуска — `AD_PASS_OVER`.
- **Огонь — механикой аддона:** снаряды `AirDefenseSVA.Projectile` (стр. 136) с `hx/hy/hz` = пушка поста, `homeCells` = клетки площадки 5 × 5 и парапета (снаряд выходит через свою постройку), `AirDefenseSVA.INSTANCE.fire(p)` (стр. 838); прицел — `BallisticsMath.gunAim` (стр. 128), ракеты — `steer` (стр. 162); линия огня — `AirDefenseSVA.losClear` (стр. 520) от пушки; стреляет ближайший пост с открытой линией; урон и темп — как у существующей зенитки аддона (TODO(balance)); запись в журнал пусков (`launchLog`, стр. 1094). Клиентские трассеры / ракеты — существующий `AirDefenseClientSVA`.
- Без аддона посты молчат (ядро). Конфиг `airdefense.embassyAd` выключает ПВО посольства (посты остаются декором).
- LAN вдвоём: решает сервер; допуск, прикрытие и пропуск — по каждому игроку (ядро по UUID); двое в одном борту — допущен любой → борт не цель.
